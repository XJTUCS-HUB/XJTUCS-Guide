## Background

物理内存空间有限的情况下，想要运行多道程序，可以把所有的内存和外存虚拟为一个大的逻辑空间（比物理地址空间大得多）

理论原理：局部性原理，分为时间局部性和空间局部性

虚存的逻辑容量由系统的**寻址能力**和**外存容量**之和决定

比较Cache和虚存：
- Cache解决速度不匹配问题，由硬件完全实现
- 虚存解决内存容量不足问题，由操作系统与硬件共同实现

## Demand Paging

Page的动态加载：只在需要的时候才把Page加载到内存

Demand paging= paging + page fault + page replacement 

实现方法：Lazy swapper 惰性交换器

### 缺页错误
在查页表时，可能发现这个虚拟地址是无效的

缺页率=缺页数量/请求页面数量

![Chapter 9 Virtual Memory__1](https://pub-e7c93c0b727d457c895b016a26707158.r2.dev/2026/11/Chapter%209%20Virtual%20Memory__1.png)

需要会算总时间（p是缺页率）
$$EAT = (1 – p) * memory \ access + p (page \ fault\  overhead + swap\  page \ out + swap \ page \ in+ restart \ overhead)$$

处理缺页错误的**主要步骤**：
1. 操作系统查找内部页表确认无效引用
2. 寻找空闲物理块
3. 将缺失页面从外存读入物理内存
4. 修改页表项
5. 重新执行被中断的指令

### FIFO 算法
优先淘汰最早调入内存的页面
实现简单但性能较差，容易产生Belady异常
![Chapter 9 Virtual Memory__2](https://pub-e7c93c0b727d457c895b016a26707158.r2.dev/2026/11/Chapter%209%20Virtual%20Memory__2.png)

上图的情况中，帧数变多反而性能下降了
### Optimal 算法
淘汰最长时间内不再被访问的页面
这是理想化算法且无法预知未来，主要用于理论性能评估

### LRU 算法
淘汰最近一段时间最少被访问的页面。依据局部性原理，过去近期未被使用的页面在未来短期内被使用的概率也较低。

实现方法：计数器，堆栈，近似
![Chapter 9 Virtual Memory__3](https://pub-e7c93c0b727d457c895b016a26707158.r2.dev/2026/11/Chapter%209%20Virtual%20Memory__3.png)
每个页面保留一个8位的字节，定时器中断定期地将调用过的页面设置为1，再定期丢弃最低位

### 计数器算法

## Thrashing

抖动指进程分配的物理页面过少导致持续发生缺页，进程大部分时间用于页面的换入和换出，实际有效计算时间极少

CPU 利用率下降促使操作系统引入更多并发进程，这会进一步加剧内存争夺，导致系统性能下降

可能导致系统抖动的存储分配方式：**页式**和**段页式**（可变分区和段式不会）
## Working-Set Model

工作集模型基于**局部性原理**

工作集窗口是一个定值，表示过去的内存访问窗口大小。工作集大小指进程在窗口内访问的不同页面集合。

若所有进程的工作集大小总和超过系统可用物理帧总数，系统就会发生抖动；操作系统通过监控工作集来动态调整分配给进程的帧数。

### Page-Fault Frequency

通过调节缺页率来控制抖动

操作系统设定缺页率的上下限：
- 高于上限时，给进程分配更多物理帧
- 低于下限时，回收进程多余的物理帧

## Memory-Mapped Files

核心理念是让进程的一段虚拟地址空间与磁盘文件直接关联。
任何进程的写操作都会修改虚拟内存中的数据，并且可以被映射文件同一部分的所有其他进程看到

1. 映射建立
2. 访问执行

具体的流程见PPT，这种方法不适合小文件，且有数据丢失的风险

## Allocating Kernel Memory

内核内存分配**不同于用户进程**，通常需要满足特定数据结构的频繁申请与释放

常用管理算法：
- 伙伴系统：将内存划分为大小为二的幂次的连续物理块，能够快速合并相邻空闲块以减少外部碎片
- Slab 分配：将内存划分为特定的缓存区，专门用于存储同类内核对象，避免内部碎片并显著提高分配效率

## 其他的考量

预分页：在进程运行初期预先调入若干可能用到的页面，减少启动阶段的连续缺页次数。
页面大小：
  - 大页面能够减少页表大小并提高缓存命中率，减少I/O time，但会增加内部碎片
  - 小页面能够减少内部碎片（更准确地匹配程序局部性），但会导致页表庞大并降低缓存命中率
工作集保存在TLB里，TLB Reach = (TLB Size) * (Page Size)

PPT上举了Windows XP和Solaris的例子
