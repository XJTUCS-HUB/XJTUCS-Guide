# 公告：Pull Request 内容格式检查已上线

为了让格式问题在合并前被发现，减少 Astro 构建失败，本仓库现已上线 Pull Request 自动检查机器人。

当 PR 标记为 Ready for review 后，bot 会检查本次提交涉及的确定性仓库规则，包括：

- 内容目录和文件命名；
- Frontmatter 格式及必填字段；
- 课程代码和课程引用；
- 贡献者目录命名；
- Markdown 与 PDF 的配对关系；
- 其他可能导致仓库构建失败的内容结构问题。

检查结果分为两类：

- `FAIL`：阻断问题。必须修复，`Build / build` 通过前任何人都不能正常合并 PR。
- `WARN`：非阻断警告。不会自动阻止合并，但请尽量修复；无法或无需修复时，请在 PR 中说明原因，供维护者判断。

## 收到检查结果后怎样处理

不论收到 `FAIL` 还是 `WARN`，都不需要关闭或重新创建 PR。请直接：

1. 在原 PR 对应的分支上修改文件；
2. 创建新的 commit；
3. push 到原分支；
4. 等待自动检查重新运行。

bot 会更新原有评论，而不是要求重新投稿。评论更新可能有短暂延迟，GitHub 页面也不一定实时刷新。如果仍看到旧结果，请先确认 `PR Policy / danger` 已经运行完成，再刷新 PR 页面。

`WARN` 不要求为了“清空评论”而重新开 PR。如果警告符合预期，可以直接在原 PR 中解释原因并等待维护者审查。

## 检查范围

bot 只检查已经编码的格式和仓库结构规则，不判断内容是否真实、是否侵权、是否包含隐私、是否存在泄题风险，也不代替人工审查。最终是否合并，仍由仓库维护者结合自动检查、构建结果和内容审查决定。

完整规则、提交前本地检查命令和常见修复方式见 [Danger.js PR 审查使用说明](../../danger-review.md)。
